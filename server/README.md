# warket-api

The warket server: a Cloudflare Worker (Hono, Zod, Drizzle) with a D1 database stored in the EU.
The contract is in [API.md](API.md).

The server never stores a vault key. It keeps a fingerprint (`SHA-256`) of it, and a share key only
reads. Request logs are switched off in `wrangler.jsonc` because requests carry the vault key in a header.

## Run it locally

```bash
cd server
npm install
npm run db:migrate   # create the tables in the local database (.wrangler/)
npm run dev          # http://localhost:8787
curl http://localhost:8787/v1/health
```

## Check and test

```bash
npm run check   # generate Cloudflare types, then type-check the server and the tests
npm test        # API tests inside the real Workers runtime, with a fresh local database
```

## Change the database

1. Edit `src/db/schema.ts`.
2. `npm run db:generate -- --name <what-changed>` writes a new file in `migrations/`.
3. `npm run db:migrate` applies it locally. `npm test` applies it in tests automatically.
4. `npm run db:migrate:remote` applies it to the real database (only after the tests pass).

## Deploy

`npm run deploy`. Apply remote migrations first when the schema changed.

## Files

```
src/index.ts         app: headers, CORS, rate limits, body size, access, routes, errors
src/auth.ts          who is calling (Bearer = owner, Share = viewer)
src/validation.ts    input rules and limits (Zod), plain-sentence error messages
src/serialize.ts     response shapes, built field by field
src/routes/          lists, assets, export/import, share and delete vault
src/db/schema.ts     tables (Drizzle)
migrations/          SQL migrations (generated by drizzle-kit)
test/                API tests
```
