# warket: native iOS

A native **SwiftUI** port of the warket web app: a privacy-first asset
watchlist. It talks to the **warket server** (`../server`, a Cloudflare Worker
with a D1 database), the same one the web app uses. Identity is a 12-word seed
phrase, SHA-256 hashed on device into a `vault_hash`. No accounts, no emails.

> Source web app: repository root (`../`). Full plan and milestones live at
> `Obsidian/Projects/warket-native/mvp-implementation-plan.md`.

## Status

**MVP complete (M0 to M5)** plus sharing, export/import and title auto-fetch.
Core flow: unlock, lists, assets, full CRUD, drag-reorder, search and tag
filtering, in the system fonts (the brand serif only in the wordmark).

## Features

- **Unlock**: enter or generate a 12-word phrase. The phrase is hashed locally
  and **never leaves the device**; only the hash is sent to the server, in the
  `Authorization` header. A generated phrase must be confirmed as saved
  ("I saved my 12 words") before the vault opens; Copy keeps the words on this
  iPhone only and clears them after 2 minutes. "Keep me signed in" remembers
  the hash across launches, in the Keychain (this device only, not in backups).
  A share key pasted here opens that vault read-only.
- **Lists**: native List *or* 2-column grid (persisted toggle), create, edit,
  delete, search (by list name *or* a contained asset's name/ticker), tag-chip
  filtering, drag-reorder. If loading fails, a "Try Again" button reloads.
- **Assets**: add, edit, delete, search, tag filtering, drag-reorder.
- **Asset detail**: image, summary, **markdown notes** (custom block renderer:
  headings, lists, quotes, code, inline styles), tags, tappable resource links
  with favicons. Only web links (http and https) open.
- **Asset editor**: name and ticker (ticker optional), summary (250-character
  limit, counted like the database does), markdown notes with a live
  Write/Preview toggle, tags, image URL, resources (add, remove, reorder).
  A resource link's title can be fetched automatically.
- **Sharing**: create a read-only share key for the vault. The server refuses
  every change made with a share key.
- **Export and import**: JSON files compatible with the web app. Import merges
  lists with the same name and is all or nothing: a broken file writes nothing.
- **Account**: About screen (version, how the vault works, Privacy Policy and
  Support links, also reachable from the unlock screen). Lock vault asks first.
  Delete vault erases everything on the server after two confirmations.
- **Errors**: people see plain sentences (the server's own message, "No
  connection", or a generic one). The technical error goes to the log.
- **Design**: system backgrounds, lists and buttons. Liquid Glass comes from the
  system bars and controls (iOS 26); the content itself sits on plain surfaces.
- Haptics, toast banners, light and dark mode (follows the system).

## Tech

- SwiftUI, Swift. iOS 26+, Liquid Glass from the system components.
- No third-party packages. `Core/APIClient.swift` talks to the server with
  `URLSession`, following the contract in `../server/API.md`. The server address
  is `API_BASE_URL` in `warket/Config/Info.plist` and ships inside the app.
- Project generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from
  `project.yml`; the `.xcodeproj` is gitignored.

## First-time setup

1. **Install XcodeGen** (one-time): `brew install xcodegen`
2. **Add your signing team**: copy the template, then fill in your Apple
   signing team ID (`DEVELOPMENT_TEAM`):
   ```bash
   cd warket-ios
   cp warket/Config/Secrets.xcconfig.example warket/Config/Secrets.xcconfig
   # then edit warket/Config/Secrets.xcconfig
   ```
   `Secrets.xcconfig` is gitignored. Keeping the team there means
   `xcodegen generate` never erases it.
3. **Generate the Xcode project**: `xcodegen generate`
4. **Run on your iPhone**: `open warket.xcodeproj`, pick your iPhone as the run
   destination, press ⌘R.

After adding or removing files or changing project config, re-run `xcodegen generate`.

## Hash parity (critical)

The Swift hash must match the web app's JS hash **byte-for-byte**, or existing
vaults won't open. `warketTests/HashParityTests.swift` asserts the reference
vector (the web tests check the same value). It must pass. Share keys are made
by the server, whose tests hold the share key vector.

